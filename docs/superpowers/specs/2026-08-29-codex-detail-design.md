# 어드민 도감 상세 페이지 — 설계

- 작성일: 2026-08-29
- 대상: `my-heritage-web` (구현) · `my-heritage-planning` (정책 SoT)
- 관련 화면: A-04 도감 전체 검색 · A-05 검증 큐 · A-01 상세 도감 탭
- 의사결정 예정: D-267 ~ D-269

## 1. 문제

도감 하나를 손보려면 화면·모달 네 곳을 오간다.

| 하려는 일 | 지금 |
|---|---|
| 명칭 고치기 | 목록 행의 `CodexEditForm` 모달 |
| 종류 지정 | 카테고리 상세 도감 탭의 셀렉트 (D-257) |
| 언어 alias | A-07 alias 관리 |
| 키 alias | A-07 또는 후보 큐 |
| 검증 토글 | 목록 행 버튼 |

**한 도감의 전모를 볼 자리가 없다.** A-05 검증 큐에서 "이게 맞나"를 판단하려면 alias·키·종류를 함께 봐야 하는데 흩어져 있다.

## 2. 라우트

```
/admin/codex/[codexId]     도감 상세 (신규)
```

진입점 셋 — A-04 전체 검색 · A-01 상세 도감 탭 · A-05 검증 큐 — 전부 **명칭 클릭**으로 들어온다.

⚠️ `/admin/codex/aliases`·`/merge`·`/verification` 이 이미 있으므로 `[codexId]` 가 그 정적 세그먼트와 충돌하지 않는지 확인한다. Next 는 정적 세그먼트를 우선하므로 안전하지만, **`aliases` 라는 id 를 가진 도감은 없다**는 전제를 명시해 둔다(cuid 라 불가능).

## 3. 편집 범위 — 기존 액션 재사용

| 항목 | 액션 | 컴포넌트 | 상태 |
|---|---|---|---|
| 명칭 · 다국어 설명 | `updateCodexItem` | `CodexEditForm` | 있음 |
| 종류 | `setCodexSubtype` | `CodexSubtypePicker` | 있음 (D-257) |
| 언어 alias | `setCodexAliases` | `CodexAliasEditor` | 있음 |
| 키 alias | `setCodexKeyAliases` | `CodexKeyAliasEditor` | 있음 |
| 검증 | `setCodexVerification` | `AdminActionButton` | 있음 |
| **고유값(매칭 키)** | — | — | **만들지 않는다** |

**새 액션은 재수집 하나뿐이다.** 나머지는 흩어진 것을 한 화면에 모으는 일이다.

### ⚠️ 고유값을 편집 대상으로 두지 않는다

`normalizedKey` 가 바뀌면 함께 움직여야 하는 것이 많다 — 유일성 범위(`@@unique([scopeId, normalizedKey])`), `CodexMatchKey` 의 PRIMARY 행, 그리고 **이미 연결된 유저 아이템의 매칭 의미**.

값이 틀렸으면 **병합(A-06)이 올바른 도구다.** 옳은 도감으로 흡수시키면 아이템도 함께 옮겨간다(D-181).

## 4. 재수집 — **제안만 하고 쓰지 않는다**

```
[재수집] → AI 조사 → 제안값을 현재값과 나란히 표시 → 사람이 [적용] / [무시]
```

- `researchCodexEntries` 를 **이 도감의 브랜드·종류로** 호출한다
- **DB 에 쓰지 않는다.** 적용은 기존 `updateCodexItem` 을 탄다
- **로컬 전용** (D-146·D-185) — 프로덕션에선 숨기지 않고 이유를 붙여 비활성

### "스킬을 사용해서 정밀하게" 를 어떻게 구현하나

`.claude/skills/collecting-catalog-data/SKILL.md` 는 **에이전트용 문서**라 런타임이 읽지 않는다. 대신 **그 스킬이 정리한 규칙을 힌트 조립에 넣는다**:

| 규칙 | 출처 |
|---|---|
| 종류를 힌트에 박는다 | D-262 (버너가 침낭으로 저장됨) |
| 혼동하기 쉬운 이웃을 명시적으로 배제 | D-266 ("완성차 모델명은 내지 마세요") |
| **0건이 정답일 수 있다** | D-262 (안 만드는 브랜드에 억지로 채우지 않는다) |
| 브랜드 게이트에 종류를 넘긴다 | D-264 |

한 건짜리 재수집은 **브랜드·종류·현재 명칭이 이미 정해져 있어** 대량 수집보다 힌트를 좁게 줄 수 있다 — 그것이 "정밀"의 실체다.

## 5. 검증완료 — **사람이 누른다**

`setCodexVerification` 을 그대로 쓴다. **재수집이 자동으로 찍지 않는다.**

### ⚠️ D-185 를 지킨다

D-185 가 이 기능의 **핵심 판단**으로 적어둔 것:

> 어드민이 표를 훑기는 하지만 **10건의 레퍼런스 번호를 눈으로 검증할 수는 없다.** 그것을 `검증됨` 으로 넣으면 AI 가 지어낸 값이 **신뢰 배지를 달고** 그 물건을 가진 모든 유저에게 노출된다.

구조로도 막아뒀다:

> `verification` 을 인자로 받으므로 Server Action 으로 두지 않았다 — 액션이면 클라이언트가 `VERIFIED` 로 직접 호출해 **배지를 무의미하게 만들 수 있다**

"수집 → 자동 검증" 은 그 방어를 정확히 우회하는 경로다. 오늘만 해도 AI 가 버너를 침낭으로(D-262), 부츠를 캠핑으로(D-216) 냈다.

### ⚠️ 다만 상황이 달라진 부분은 명시한다

D-185 가 "눈으로 검증할 수 없다" 고 본 것은 **목록에서 10건을 훑는 상황**이다. 상세는 **한 건씩 보는 화면**이고 alias·키·종류·보유자가 한자리에 있다 — **실제로 확인이 가능하다.**

그래서 상세의 `검증완료` 버튼은 D-185 와 충돌하지 않는다. **A-05 검증 큐가 하기로 한 일을 더 잘하는 자리**다.

## 6. 화면 구성

```
도감 상세 — Trek Domane SLR Frameset                    [검증완료]
────────────────────────────────────────────────────────
기본        명칭 [........]  · 고유값 trek|domaneslrframeset (읽기 전용)
            카테고리 자전거  · 종류 [프레임 ▼]  · 검증 미검증
            보유자 0명  · 등록 2026-08-29

재수집      [재수집]  로컬 전용
            ┌ 제안된 값 ──────────────────┐
            │ model  Domane SLR Frameset  │
            │        → 현재값과 동일       │
            │ [적용] [무시]                │
            └─────────────────────────────┘

alias       언어 alias (검색용)   [편집]
            키 alias (매칭용)     [편집]

설명        검증본만 3개 언어 (FR-07-A-05)

병합        흡수한 도감 · survivor 링크
```

⚠️ **설명 편집은 검증본에만 연다.** 미검증 도감의 설명 자리는 **유저가 쓴 원문**이다(FR-07-A-05) — 어드민 문장을 넣으면 유저가 쓴 것으로 읽힌다. `updateCodexItem` 이 이미 그렇게 막고 있다.

## 7. 검증

이 저장소에는 테스트가 없다. `pnpm lint` · `pnpm typecheck` · 실제 요청으로 한다.

| 확인 | 기대 |
|---|---|
| `/admin/codex/[유효 id]` | 200 |
| `/admin/codex/aliases`·`/merge`·`/verification` | **여전히 200** (정적 세그먼트 우선) |
| 없는 id | 404 |
| 미검증 도감 | 설명 편집 **안 보임** |
| 검증본 | 설명 편집 보임 |
| 재수집 | DB 가 **안 바뀜** — 제안만 표시 |
| 검증완료 | `verifiedBy`·`verifiedAt` 기록 |
| 운동 도감 | 200 — 브랜드가 없고 매칭 키가 빈 배열이라 재수집이 **비활성이어야** 한다 |

## 8. 하지 않는 것

| 항목 | 이유 |
|---|---|
| 고유값 편집 | 유일성·매칭 키·유저 아이템이 함께 움직인다. 병합(A-06)이 올바른 도구 |
| 카테고리 이동 | D-216 판단 — 일회성 스크립트로 |
| 재수집의 자동 적용·자동 검증 | D-185 의 핵심 판단 |
| 병합·alias 큐 화면 대체 | 상세는 **보기·편집**이고 큐는 큐다. 큐는 "무엇이 남았나"를 보는 자리 |
| 목록의 `CodexEditForm` 모달 제거 | 목록에서 명칭만 빨리 고치는 경로는 남긴다. 상세는 전모를 보는 자리 |

## 9. 기록할 의사결정

- **D-267** 도감 상세 신설 — 흩어진 편집을 한자리로. 고유값은 편집 대상이 아니다
- **D-268** 재수집은 제안만 한다 — 스킬이 정리한 규칙을 힌트에 넣는 것이 "정밀"의 실체
- **D-269** 상세의 검증완료는 D-185 와 충돌하지 않는다 — "목록에서 10건 훑기" 와 "한 건씩 보기" 는 다르다

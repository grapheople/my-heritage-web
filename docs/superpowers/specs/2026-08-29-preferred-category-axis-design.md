# 관심 카테고리를 축으로 — 선택 1개에서 내 관심사 집합으로

- 작성일: 2026-08-29
- 대상: `my-heritage-web`
- 관련 결정: **D-137**(카테고리 관통 축) · D-124·D-126(선호 카테고리) · D-069·D-109(빈 화면 금지)
- 의사결정 예정: D-271 ~ D-273

## 1. 지금 구조

D-137 이 카테고리를 **"필터가 아니라 서비스를 관통하는 축"** 으로 만들었다. 항상
하나가 선택돼 있고 **홈·검색·마켓·도감**이 그 안에서만 동작한다.

```
resolveCategory(fromUrl?) → { key, chosen, keys }
  1. URL ?category=      공유 링크가 이긴다
  2. 쿠키                 비로그인도 유지
  3. 선호 카테고리 첫 항목  가입 때 고른 것 (D-124)
  4. 첫 활성 카테고리      첫 방문 — 이때만 선택 화면
```

| 화면 | 지금 |
|---|---|
| 홈·검색·마켓·도감 | **선택된 1개** |
| 아이템 등록 | 전체 8개 (`CATEGORY_KEYS`) |
| 내 방 | 제외 — 자기 물건은 넘나들며 본다 (D-068·D-089) |
| 설정 편집 | **이미 있다** (`profile-form.tsx`) |

## 2. 바뀌는 것 — 축의 **단위**가 바뀐다

D-137 의 구조를 없애지 않는다. **단위가 "선택된 1개" 에서 "내 관심사 집합" 으로**
바뀔 뿐이다.

**D-137 의 목적은 그대로 지켜진다** — "시계 컬렉터가 캠핑 텐트를 스쳐 지나가지
않게" 는 관심사로 걸러도 성립한다. 오히려 시계+캠핑을 함께 모으는 사람이
둘 다 보게 된다.

| 화면 | 바뀜 |
|---|---|
| 홈·검색·마켓 | **관심사 전체** |
| 도감 | 선택 1개 유지 — **고를 수 있는 목록만 관심사로** |
| 아이템 등록 | 전체 8개 → **관심사 전체** |
| 내 방 | 변경 없음 |
| 설정 | 변경 없음 (이미 있다) |

### 왜 도감만 하나를 고르나

도감은 **제품 사전을 훑는 화면**이라 한 카테고리 안에서 깊이 보는 것이 맞다.
시계 레퍼런스를 찾는 중에 텐트가 섞이면 목록이 못 쓰게 된다. 홈·마켓은
**둘러보는** 화면이라 합쳐도 된다.

## 3. `category-scope.ts` 에 함수를 하나 더 둔다

```ts
// 도감 전용 — 하나를 고른다 (지금 그대로, 목록만 관심사로 좁힌다)
resolveCategory(fromUrl?): Promise<{ key; chosen; keys }>

// 홈·검색·마켓·등록 — 집합을 낸다 (신규)
myCategoryKeys(): Promise<string[]>
```

**⚠️ 같은 파일에 둔다.** `category-scope.ts` 가 이미 축의 단일 출처다. 규칙이
흩어지면 조용히 갈린다 — 이 세션에서 D-190·D-197·D-270 로 **세 번** 겪었다.

## 4. ⚠️ 빈 집합은 **전체**로 떨어진다

```
로그인 + 관심사 있음  → 그 집합
로그인 + 관심사 없음  → 전체
비로그인             → 전체
```

관심사가 없다고 화면을 비우면 **둘이 동시에 깨진다**:
- **D-069** 관람자가 콘텐츠 대신 벽을 만난다
- **D-109** 크롤러가 받는 HTML 에 아이템이 하나도 없다 — `Zroom` 으로 검색해도
  서비스가 안 나오던 상태로 되돌아간다

**빈 배열을 반환하지 않는다.** 호출부가 `[]` 를 "아무것도 안 보여준다" 로
해석할 여지를 남기지 않기 위해, `myCategoryKeys()` 는 **항상 1개 이상**을 낸다.

## 5. 홈의 `CategoryGate` 는 걷어낸다

지금은 "고른 적 없으면 선택 화면을 덮는" 장치다(`page.tsx:116`). 축이 집합이
되면 **홈에서 덮을 이유가 없다** — 관심사가 없어도 전체를 보여주므로 벽이 아니다.

**도감에는 남긴다.** 거기서는 여전히 하나를 골라야 하고, 고른 적이 없으면
무엇을 보고 있는지 알 수 없다.

## 6. 호출부

| 파일 | 변경 |
|---|---|
| `src/lib/category-scope.ts` | `myCategoryKeys()` 신규 |
| `src/app/[locale]/(user)/page.tsx` | `resolveCategory` → `myCategoryKeys`, `CategoryGate` 제거 |
| `src/app/[locale]/(user)/market/page.tsx` | 같은 교체 |
| `src/app/[locale]/(user)/search/page.tsx` | `?category=` 단일 → 집합 |
| `src/app/[locale]/(user)/codex/page.tsx` | `keys` 를 관심사로 좁힘 |
| `src/components/domain/item-form.tsx` | `CATEGORY_KEYS` → 서버가 내려준 관심사 |
| `src/lib/data/market.ts` | `category?: string` → `categories?: string[]` 추가 |
| `src/lib/data/feed.ts` | **변경 없음** — `categories?: string[]` 가 D-124 로 이미 있다 |
| `src/app/sitemap.ts` | **변경 없음** — 크롤러는 전체를 봐야 한다 |

⚠️ **sitemap 은 건드리지 않는다.** 색인은 특정 유저의 관심사와 무관하다 —
관심사로 좁히면 D-109 가 깨진다.

## 7. 검증

| 확인 | 기대 |
|---|---|
| 관심사 2개인 유저의 홈 | 두 카테고리 아이템이 **함께** 보인다 |
| 관심사 없는 유저 / 비로그인 | **전체** — 비지 않는다 |
| 도감 | 여전히 하나 선택. **목록에 관심사만** |
| 아이템 등록 | 관심사만 (전체 8개 아님) |
| 내 방 | 변경 없음 — 전 카테고리 |
| `/sitemap.xml` | URL 수 **변화 없음** |
| 홈 HTML | 로그아웃 상태에서 아이템이 **들어 있다** (D-109) |

## 8. 하지 않는 것

| 항목 | 이유 |
|---|---|
| 설정 화면 신설 | 이미 있다 (`profile-form.tsx`) |
| 관심사 최소 1개 강제 | 빈 집합이 전체로 떨어지므로 불필요. 강제하면 온보딩이 막힌다 |
| 내 방에 관심사 적용 | 자기 물건은 카테고리를 넘나들며 본다 (D-068·D-089) |
| sitemap 에 관심사 적용 | 색인은 유저 무관 (D-109) |
| 쿠키 축 제거 | 도감이 여전히 쓴다 |
